## 新需求：多人问卷与自动汇总

- 希望将不同岗位的题目通过问卷或网页发送给多位评分人。
- 评分人提交后，答案自动回传并汇总到管理员侧。
- 已确认的第一版规则：
  1. 评分人通过职位共用链接进入问卷，不需要注册账号；填写姓名和所在部门后，系统只展示预分配给该评分人的任务，评分层级由任务确定且不能自行修改。
  2. 评分人姓名必填，填写处明确标注“匿名提交”。
  3. 管理员可以查看评分人姓名与完成状态，用于去重和管理；被评估人及最终报告不显示评分人姓名。
  4. 评分人提交后只显示“提交成功”，不能查看个人分数或汇总结果。
  5. 预计使用规模：每月不超过 50 名被评估人，每人约 3—10 位评分人。
  6. 第一版管理员后台使用一个固定访问密码；密码必须保存在服务端环境变量中，不能写入前端代码。
  7. 评分人提交后不能自行修改；如需重填，由管理员作废原提交并填写原因，再把任务恢复为待提交。原答卷保留但不参与汇总。
  8. 每个职位使用一个长期共用问卷链接；链接自动进入该职位当前开放批次，不为每名被评估人单独生成链接。
  9. 评分人不能自由填写或从全名单选择被评估人；管理员预先维护人员并分配“谁评价谁”，评分人只查看自己的任务。
  10. 管理后台提供独立的“被评估人名单管理”功能，可随时新增、修改、启用或停用人员。人员使用内部唯一 ID 关联历史提交，修改显示信息不会破坏历史数据；已有评分记录的人员默认不做物理删除。
  11. 管理员创建“评估批次”（例如“2026年第三季度能力评估”），被评估人名单和评分提交均归入批次；同一人的不同批次结果用于历史对比。
  12. 同一职位同一时间只允许一个开放批次；职位共用链接自动进入该批次。旧批次关闭后不再接收提交，仅供管理员查询、汇总和历史比较。
  13. 每条预分配任务使用唯一任务 ID，且只能关联一份当前有效答卷；提交同时使用唯一幂等键防止网络重试或重复点击产生两份答卷。
  14. 管理员创建批次时设置截止时间；到期自动关闭，同时允许管理员提前关闭或延长。问卷页显示批次名称和截止时间，批次关闭后不展示可评人员，也不接受新提交。
  15. 第一版不做邮件或企业微信自动催办。管理员后台显示被评估人、评分层级、已提交人数和评分人姓名，管理员复制或查看未完成情况后，通过微信/企业微信手动提醒。
  16. 至少一个维度有效即可显示阶段性分数，结果标注总样本数、各层级和各维度有效样本数；只有六维都有有效样本才生成完整雷达图和综合分。批次关闭后结果冻结，如需修改必须重新开放并在再次关闭时生成新版快照。
  17. 最终报告仅在管理员后台查看；管理员导出 PNG 或 PDF 后自行发送给被评估人。第一版不生成被评估人可直接访问的在线报告链接，报告中不显示评分人姓名。
  18. 管理员可导出完整 Excel 明细，包括批次、职位、被评估人、评分人姓名、评分层级、每题答案、六维得分和提交时间。该文件仅供管理员使用，不作为匿名报告发送。
  19. 手机问卷按 6 个维度分页，每页 5 题，显示整体进度；未提交答案在当前设备自动保存为草稿，关闭页面后使用同一设备和浏览器可继续填写。
  20. 每题均可选择“无法判断”，该题不计分。单个评分人的某一维度至少有 3 道有效答案才计分，否则该评分人的该维度无效；最终提交前提示有效答案不足的维度。
  21. 允许评分人只提交部分有效维度；只要至少一个维度达到有效题数要求即可提交。汇总时仅纳入有效维度，无效维度视为缺失数据，不按 0 分计算。
  22. 问卷、评分与历史结果长期保存，由管理员按批次导出、归档或手动清理。涉及历史数据的删除操作需要二次确认，优先使用停用/归档而非物理删除。
  23. 技术架构采用 A 方案：EdgeOne Makers 承载公开问卷和管理员网页，腾讯云 CloudBase 承载云函数、数据库、管理员鉴权与数据导出。
  24. 系统架构与数据流设计已经用户确认：公开端与管理端共用 EdgeOne 前端，所有正式数据读写、校验、计分和权限控制均经由 CloudBase 服务端完成。
  25. 数据库结构设计已经用户确认：人员、题库版本、批次、职位当前批次、批次名单、评分提交、最终结果及操作记录分开保存；人员和题库采用稳定版本标识，答卷作废而非直接物理删除。
  26. 评分人问卷流程已经用户确认：职位链接自动进入当前开放批次，评分人填写姓名和所在部门并选择自己的预分配任务，层级只读；六维分页作答且本机自动保存草稿，服务端完成有效性、截止时间、幂等和重复提交校验，成功页不展示任何得分。
  27. 评估任务采用预分配模式：管理员在批次内为每名被评估人配置具体评分人及其上级/平级/下级关系，使后台能够准确显示已提交、未提交和待提醒人员。
  28. 评分人身份采用“姓名 + 所在部门”匹配预分配任务，不使用核验码或账户；姓名和部门均需规范化后匹配。若两人姓名与部门均相同，管理员使用更细的部门名称区分。
  29. 管理员后台设计已经用户确认：包含工作台、人员名单、评估批次、任务分配、完成进度、答卷管理、能力结果和批次归档；支持 Excel 批量导入、复制上一批次、手动提醒名单、答卷作废重填及操作日志。
  30. 若被评估人的六个维度中仍有维度没有有效样本，则不绘制完整雷达图；已有维度显示实际分数，缺失维度显示“待补充”，待六维都有有效样本后再生成雷达图。
  31. 六维计分规则已经用户确认：A-E 为 20/40/60/80/100，“无法判断”为缺失；单人单维至少 3 道有效题；先求同层级均分，再按上级/平级/下级 50%/30%/20% 加权，缺失层级按有效权重归一；六维完整后等权计算综合分。
  32. 历史趋势只对比同一人员、同一职位且六维含义一致的批次；换岗前后的能力图分别保存和展示，并标注维度不同，不进行雷达图叠加或直接数值比较。
  33. 能力图与导出设计已经用户确认：蓝白风格六维雷达图仅在六维完整时生成；同岗上次结果用浅蓝虚线叠加；PNG 为匿名单页能力卡，PDF 为 A4 两页报告，Excel 包含汇总、分层、答卷明细和任务进度四个工作表且仅管理员可导出。
  34. 异常处理、安全、备份和验收标准已经用户确认；七个设计部分全部通过，并已合并为正式规格文档 `docs/superpowers/specs/2026-08-13-multi-rater-questionnaire-design.md`。
