# 岗位六维能力评估：多人问卷与自动汇总系统设计规格

- 状态：用户已于 2026-08-13 确认规格通过
- 日期：2026-08-13
- 适用版本：第一版多人在线评估系统
- 现有项目：`capability-radar-app`

## 1. 目标与成功标准

把现有的单机能力图生成器升级为一个可长期使用的在线评估系统。管理员预先维护人员、评估批次和评分任务；评分人通过职位公共链接匿名提交行为选择题；系统在云端计算、汇总并保存结果；管理员查看进度、能力图、历史对比并导出报告。

第一版成功标准：

1. 支持销售、商务、项目经理、技术交付、线下运营、IP运营、内容发行 7 个职位。
2. 每个职位固定 6 个岗位维度，每个维度 5 题，共 210 道题。
3. 每月支持不超过 50 名被评估人，每人约 3—10 名评分人。
4. 管理员能够准确知道每个预分配任务由谁完成、谁尚未完成。
5. 评分人和被评估人不需要注册账户；管理员使用一个服务端固定密码。
6. 评分人姓名仅供管理员核对，匿名报告和公开接口均不披露评分人身份。
7. 六维计分、多层级权重、缺失数据、历史对比和导出结果均可重复验证。
8. 正式数据以云端数据库为准，不依赖某台设备或某个浏览器。

## 2. 第一版范围

### 2.1 包含

- 职位长期公共问卷链接。
- 管理员人员名册、题库版本、评估批次和评分任务管理。
- 评分人通过“姓名 + 所在部门”匹配预分配任务。
- 手机端六维分页问卷、本机草稿、服务端提交与防重复。
- 阶段性汇总、最终结果、同职位历史对比。
- 蓝白风格六维雷达图，以及 PNG、PDF、Excel 导出。
- 管理员完成进度、答卷作废、批次关闭/重开、操作日志。
- 请求限流、管理员会话、自动备份和恢复演练。

### 2.2 不包含

- 评分人或被评估人账户体系。
- 手机号、短信、企业微信或邮箱身份认证。
- 自动发送邀请、催办或报告。
- 被评估人在线查看报告的公开链接。
- 评分人提交后自行修改答案。
- 跨职位六维结果叠加比较。
- 多管理员角色和细粒度权限。
- 被评估人自评层级；第一版仅使用上级、平级、下级。

## 3. 已接受的身份安全边界

评分人身份采用“姓名 + 所在部门”基础核对，不使用核验码或账户。该方式操作简单，但知道他人姓名和部门的人仍可能代填，不能视为强身份认证。系统通过预分配任务、限流、不可枚举的任务标识和操作日志降低风险，但不承诺消除冒名提交。

如果两名评分人的姓名和部门完全相同，管理员必须在人员档案中使用更细的部门名称加以区分，例如“研发中心—客户端组”。系统不允许在同一批次中存在无法区分的评分任务。

## 4. 总体架构

```text
评分人手机端                      管理员电脑端
职位专属问卷链接                  /admin 管理后台
        │                              │
        └────── EdgeOne Makers 前端 ───┘
                         │ HTTPS API
                  CloudBase HTTP 云函数
             鉴权、校验、幂等、计分、汇总、导出
                         │
                  CloudBase 文档型数据库
        人员、题库、批次、任务、答卷、结果、日志
                         │
                 加密备份存储（保留90天）
```

### 4.1 EdgeOne Makers

- 承载公开问卷和管理员单页应用。
- 负责表单交互、本机草稿、雷达图渲染和匿名报告排版。
- 不保存管理密码、数据库密钥或服务端计分秘密。
- 前端展示的分数只能来自 CloudBase 计算结果。

### 4.2 CloudBase

- HTTP 云函数提供公开接口和管理接口。
- 所有正式数据读写、提交校验、计分、汇总和权限控制均在服务端完成。
- 文档型数据库保存业务数据，并使用事务和索引保证关键状态一致。
- 定时函数负责批次到期处理和每周备份。

### 4.3 生产域名

建议使用同一主域名下的两个子域名：

- `app.<主域名>`：EdgeOne 前端。
- `api.<主域名>`：CloudBase HTTP API。

API 仅允许正式前端域名跨域访问。生产环境启用 HTTPS；如需中国大陆节点稳定访问，主域名需要完成 ICP 备案。

## 5. 前端路由与模块边界

### 5.1 路由

- `/q/:roleCode`：职位公共问卷入口。
- `/admin/login`：管理员登录。
- `/admin`：管理员工作台。
- `/admin/people`：人员名单。
- `/admin/batches`：批次列表与新建向导。
- `/admin/batches/:batchId/tasks`：任务分配及完成进度。
- `/admin/batches/:batchId/submissions`：答卷管理。
- `/admin/results/:participantId`：能力结果、历史对比和导出。

### 5.2 模块

- `role-question-bank`：七个职位、六维定义和版本化题目。
- `questionnaire-flow`：身份匹配、任务选择、六页作答、草稿和提交。
- `assessment-admin`：人员、批次、任务和答卷管理。
- `scoring-engine`：纯函数计分、层级均分、权重归一和样本统计。
- `result-report`：能力图、历史对比、PNG/PDF 排版。
- `excel-export`：四工作表管理员明细导出。
- `api-client`：统一请求、错误转换、管理员会话和重试。

现有雷达图、角色配置和导出样式可复用；现有“管理员手工录入 0—100 分”的公开主流程不再作为正式在线问卷入口。旧浏览器 `localStorage` 历史不自动迁移到云端，因为它缺少题目答案、任务和评分人信息；原有本地数据不会被主动删除。

## 6. 数据模型

所有业务文档包含 `createdAt`、`updatedAt`，所有时间以 UTC 存储、以 Asia/Shanghai 展示。

### 6.1 `people` 人员档案

- `id`：永久内部 ID。
- `name`、`normalizedName`。
- `department`、`normalizedDepartment`。
- `currentRoleId`：当前职位；评分人可以为空。
- `canBeEvaluatee`、`canBeRater`。
- `status`：`active | inactive`。

姓名、部门和职位修改只影响后续批次，不回写历史快照。已有历史记录的人员不物理删除。

### 6.2 `questionnaire_versions` 题库版本

- `id`、`roleId`、`version`、`status`。
- 六维稳定标识、名称、类别、说明。
- 每维 5 题及 A—E 行为描述。
- 固定的答案代码与计分规则版本。
- `publishedAt`。

已发布版本不可原地修改。更改任何题目、维度名称或计分规则时创建新版本。

### 6.3 `assessment_batches` 评估批次

- `id`、`name`、`roleId`。
- `questionnaireVersionId`、`scoringVersion`。
- `assessmentDate`：报告显示的评估日期，由管理员创建批次时填写。
- `startsAt`、`deadlineAt`：开放时间和提交截止时间。
- `status`：`draft | open | closed | archived`。
- `closedAt`、`closedBy`。

一个批次只对应一个职位和一个题库版本。开放后不可更换题库版本。

### 6.4 `role_active_batches` 当前批次

文档 ID 直接使用 `roleId`，记录该职位当前开放批次 ID。创建、开放、关闭和重开批次必须通过事务更新，从结构上保证同一职位同时最多一个开放批次。

### 6.5 `batch_participants` 批次被评估人

- `id`、`batchId`、`personId`。
- `nameSnapshot`、`departmentSnapshot`、`roleSnapshot`。
- `status`：`active | removed`。

同一人员在同一批次只能出现一次。历史报告只使用快照，不受人员档案后续修改影响。

### 6.6 `assignments` 预分配评分任务

- `id`：不可预测的随机 ID。
- `batchId`、`participantId`、`raterPersonId`。
- `raterNameSnapshot`、`raterDepartmentSnapshot`。
- `level`：`superior | peer | subordinate`。
- `status`：`pending | submitted | cancelled`。
- `currentSubmissionId`、`submittedAt`。

同一批次、同一被评估人、同一评分人只能有一条任务，层级是任务属性，评分人不能修改。取消任务不删除历史。

### 6.7 `submissions` 答卷

- `id`、`assignmentId`、`batchId`、`participantId`。
- 评分人姓名、部门和层级快照。
- `questionnaireVersionId`、`scoringVersion`。
- 30 道原始答案代码。
- 每维有效题数、单人维度百分制得分和五分制得分。
- `status`：`active | voided`。
- `idempotencyKey`、`submittedAt`。
- 作废时间、作废原因和操作人。

原始答案和计算结果同时保存。管理员不能直接修改答卷；重填时作废原答卷，并把任务恢复为 `pending`。同一个 `idempotencyKey` 只能创建一次提交。

### 6.8 `result_snapshots` 最终结果快照

- `batchId`、`participantId`、`snapshotVersion`。
- 六维最终分、综合分。
- 每维各层级均分和有效样本数。
- 总有效答卷数及各层级答卷数。
- 生成时间、生成依据的有效答卷 ID 列表。

批次关闭时生成不可变快照。关闭状态不能修改任务或答卷；如需作废答卷，管理员必须先重新开放批次，旧快照标记为失效，重新关闭后生成新版快照。

即使六维数据不完整也生成关闭快照；缺失维度保存为 `null`，综合分为 `null`，并保留当时的有效样本数。开放批次的阶段性结果不写成最终快照，而是根据当前有效答卷实时计算。

### 6.9 `admin_sessions` 管理会话

- 会话 ID 摘要、创建时间、过期时间、最后活动时间。
- 原始会话令牌不写入数据库和日志。
- 两小时到期，退出后立即失效。

### 6.10 `audit_logs` 操作日志

记录人员停用、批次开放/关闭/重开、任务取消、答卷作废、报告导出和备份恢复等动作。日志包含动作、目标、时间和结果，不包含管理密码、会话令牌或完整敏感凭证。

### 6.11 关键索引与一致性

- `people(normalizedName, normalizedDepartment)`：身份匹配查询索引；允许跨组织存在同名，但批次任务必须可区分。
- `questionnaire_versions(roleId, version)`：唯一。
- `batch_participants(batchId, personId)`：唯一。
- `assignments(batchId, participantId, raterPersonId)`：唯一。
- `submissions(idempotencyKey)`：唯一。
- `submissions(assignmentId, status, submittedAt)`：答卷历史查询。
- `result_snapshots(batchId, participantId, snapshotVersion)`：唯一。

创建答卷和把任务改为已提交必须在同一事务内完成。任务的 `currentSubmissionId` 是“只能有一份当前有效答卷”的最终依据。

## 7. 服务接口

### 7.1 公开接口

- `GET /public/questionnaire/:roleCode`：返回职位、当前开放批次、截止时间和匿名说明，不返回名单、答卷或结果。
- `POST /public/tasks/lookup`：使用职位、姓名和部门匹配评分任务；只返回该评分人的任务及状态。
- `GET /public/tasks/:taskId/form`：使用身份匹配后签发的短期任务令牌读取题目。
- `POST /public/submissions`：提交任务令牌、幂等键和答案代码；成功只返回被评估人、职位和提交时间。

任务查找失败统一返回“未找到待评价任务”，不区分姓名错误、部门错误或无任务，避免枚举人员信息。

### 7.2 管理接口

- `POST /admin/login`、`POST /admin/logout`、`GET /admin/session`。
- 人员的列表、新增、编辑、启用、停用和 Excel 导入。
- 题库版本只读查询和初始发布；第一版不提供在线逐题编辑器。
- 批次的新建、开放、关闭、延长、重开和归档。
- 批次人员和任务的手动维护、Excel 导入、复制上一批次。
- 完成进度、答卷详情、答卷作废。
- 阶段性结果、最终结果、历史结果和导出数据。

所有管理接口均校验有效管理员会话。

管理写接口还必须校验允许的 `Origin`、有效 CSRF 令牌和 JSON `Content-Type`。登录后服务端签发与会话绑定的 CSRF 令牌，前端通过自定义请求头回传；CORS 仅允许正式管理前端域名并启用凭证请求。

## 8. 评分人问卷流程

### 8.1 打开链接

职位公共链接自动读取该职位当前唯一的开放批次，显示批次名称、截止时间和匿名说明。无开放批次或已过截止时间时不显示任务或题目。

### 8.2 匹配身份和任务

评分人填写姓名和所在部门。服务端统一执行：去除首尾空格、连续空白合并、全角空格转半角；中文保持原字符。匹配成功后只显示预分配给该评分人的任务。

评分层级由任务确定并只读展示。评分人不从全体被评估人名单中自由选择；如果有多条任务，可逐条完成。

身份区显示：

> 匿名提交：您的姓名仅供管理员核对完成情况，不会向被评估人展示，也不会出现在能力图或最终报告中。

### 8.3 六维分页作答

- 六个维度分六页，每页五题。
- 显示当前维度、页码和整体完成进度。
- 每题必须明确选择 A—E 或“无法判断”。
- A—E 展示完整行为描述，不只展示字母。
- 可前后翻页并修改尚未提交的答案。

### 8.4 本机草稿

草稿按 `batchId + assignmentId + questionnaireVersionId` 保存在当前浏览器，只保存未提交答案和当前页。相同设备和浏览器可以继续填写；成功提交后立即清除。页面明确提示草稿仅保存在本机，清理浏览器数据或更换设备后无法恢复。

### 8.5 提交前检查

- 每个维度显示 A—E 有效答案数量。
- 单维至少 3 道 A—E 答案才有效。
- “无法判断”不计入有效题数。
- 至少一个维度有效才能提交。
- 存在无效维度时列出维度并二次确认，但允许提交。

### 8.6 正式提交

服务端重新验证批次、截止时间、任务状态、任务令牌、题库版本、30 道答案格式和最低有效维度。服务端计算分数；前端不能提交自行计算的最终分数。

提交按钮点击后锁定并生成 UUID 幂等键。网络中断时使用同一幂等键重试；如果后台已收到，返回原成功结果而不是新建答卷。

### 8.7 成功页面

只显示提交成功、被评估人姓名、职位和提交时间，并允许返回任务列表。不能显示个人得分、雷达图、汇总分或其他评分人信息。

## 9. 管理员后台

### 9.1 登录

固定管理密码的 `scrypt` 摘要和盐值保存在 CloudBase 环境变量中。成功后由 API 设置 `HttpOnly + Secure + SameSite=Lax` 的两小时会话 Cookie；前端 JavaScript 不读取密码或会话令牌。连续失败触发按 IP 和时间窗口限流。

### 9.2 工作台

显示进行中批次、截止时间、计划任务数、已提交数、完成率、缺失维度人数及即将逾期批次。

### 9.3 人员名单

支持新增、编辑、启用、停用，按姓名、部门、职位搜索，以及使用规范模板进行 Excel 批量导入。人员永久 ID 关联历史记录。

### 9.4 批次向导

```text
填写批次信息
→ 选择被评估人
→ 分配评分人及上级/平级/下级关系
→ 检查重复、同名和遗漏
→ 开放批次
```

支持手动分配、Excel 批量导入和复制上一批次配置。开放前必须通过校验；同一职位已有开放批次时禁止开放新批次。

### 9.5 完成进度

按被评估人、评分层级和评分人展开：

- 绿色：已提交。
- 黄色：待提交。
- 灰色：已取消。
- 红色：逾期未提交。

管理员可以筛选并复制待提醒人员名单，再通过微信或企业微信手动提醒。第一版不自动发送消息。

任务提交状态与维度有效性分开显示：一份部分有效答卷会令任务变为“已提交”，但结果页仍可能显示部分维度“待补充”。

### 9.6 答卷管理

管理员可查看评分人身份、原始答案、每维有效题数、单人维度分和提交时间，不可直接改答案。开放批次中可执行“作废并允许重填”，必须填写原因；原答卷保留但不参与汇总，任务恢复待提交。

### 9.7 批次生命周期

- `draft`：可修改人员、任务、截止时间，不接收提交。
- `open`：接收提交；题库版本锁定。
- 截止时间一到，服务端立即拒绝新提交，即使定时任务尚未运行。
- 定时函数把到期批次转为 `closed` 并生成最终快照；管理员首次访问也会补偿执行未完成的关闭处理。
- `closed`：任务、答卷和最终结果冻结。
- `archived`：只读归档。
- 需要修改已关闭数据时必须重开；重开使旧快照失效，再次关闭生成新版本。

关闭存在未提交任务的批次时需要二次确认。延长截止时间只允许在批次开放或重开后执行。

管理员如需永久清理历史数据，只能对 `archived` 批次发起“永久删除”。系统先要求生成成功的最新备份，再显示将删除的人员快照、任务、答卷和结果数量；管理员必须再次输入批次名称确认。删除作为服务端批处理执行，任何一步失败都保留可重试状态；审计日志只保留批次 ID、数量、时间和操作结果，不保留已删除的评分明细。人员主档仅在不再关联其他批次时才允许另行删除，否则只能停用。

## 10. 计分规则

### 10.1 单题

| 选项 | 百分制 | 五分制 |
|---|---:|---:|
| A | 20 | 1 |
| B | 40 | 2 |
| C | 60 | 3 |
| D | 80 | 4 |
| E | 100 | 5 |
| 无法判断 | 缺失 | 缺失 |

### 10.2 单个评分人的单维得分

设某维 A—E 有效题数为 `n`：

- `n >= 3`：单人维度百分制分 = 有效题分数之和 ÷ `n`。
- `n < 3`：该评分人的该维度无效，不参与后续汇总。

评分人可以在某些维度有效、另一些维度无效。

### 10.3 同层级多人均分

对每个维度分别计算：

```text
层级维度均分 = 该层级所有有效单人维度分之和 ÷ 该层级该维有效人数
```

同一层级人数多少不会改变层级基础权重。

### 10.4 层级加权与缺失归一

基础权重：上级 0.5、平级 0.3、下级 0.2。

对每个维度分别确定有有效样本的层级集合 `L`：

```text
最终维度百分制分
= Σ(层级维度均分 × 层级基础权重) ÷ Σ(有效层级基础权重)

最终维度五分制分 = 最终维度百分制分 ÷ 20
```

只有一个层级有效时，该层级代表该维度当前结果，报告必须同时展示实际层级样本数。

### 10.5 六维完整性和综合分

- 每个维度至少有一名有效评分人时，才有该维度最终分。
- 六个维度都有最终分时，才生成闭合雷达图。
- 任一维度缺失时，已有分数照常显示，缺失项显示“待补充”，不绘制雷达图，不计算综合分。
- 六维完整时，综合五分制得分为六个最终维度五分制分的算术平均值。

### 10.6 精度

- 中间计算使用未舍入浮点值。
- 页面、PNG 和 PDF 显示两位小数。
- 雷达图使用未提前舍入的实际五分制值，坐标固定 0—5。
- Excel 包含原始答案、有效题数和高精度计算值。

## 11. 能力结果和历史对比

结果页显示姓名、部门、职位、批次、评估日期、阶段性/最终状态、六维分、综合分、总答卷数、各层级答卷数，以及每维每层级有效样本数。

历史叠加必须同时满足：

```text
同一 personId + 同一 roleId + 相同六个维度稳定标识
```

满足条件时，本次结果使用深蓝实线和半透明填充，上一次结果使用浅蓝虚线且不填充，并展示每维上次、本次和变化值。换岗前后分别展示，标注“评价维度不同，不直接比较”，不叠加、不计算变化。

## 12. 导出

### 12.1 PNG

单页匿名能力卡包含姓名、部门、职位、批次、评估日期、六维图、综合分、六维明细和样本数。阶段性结果增加明显水印，最终结果标记“最终结果”。不包含评分人身份。

文件名：`姓名_职位_批次_能力图.png`。

### 12.2 PDF

A4 纵向两页：

1. 基本信息、雷达图、综合分、历史对比。
2. 六维分数、分层样本数、变化表和简明计分说明。

阶段性 PDF 显示“数据尚未收集完成”，最终 PDF 显示“最终结果”。不包含评分人身份。

### 12.3 Excel

仅管理员可导出，包含：

1. `汇总结果`：人员、批次、职位、六维分、综合分。
2. `分层统计`：每维上级/平级/下级均分和有效人数。
3. `答卷明细`：评分人姓名、部门、层级、30 题答案、有效题数、单人六维分、提交和作废信息。
4. `任务进度`：全部预分配任务的待提交、已提交、取消或逾期状态。

导出行为写入操作日志。打开 Excel 时不得发起任何外部数据连接。

## 13. 异常处理

### 13.1 评分端

- 无开放批次：显示暂无评估，不披露名单。
- 身份不匹配：统一提示未找到任务。
- 任务已提交：显示提交时间，不能再次填写。
- 填写期间到期：保留草稿，阻止提交。
- 网络失败或服务暂不可用：保留答案，允许使用相同幂等键重试。
- 服务端已成功但响应丢失：重试返回原成功结果。
- 非法或过期任务令牌：停止提交并要求重新匹配身份。

### 13.2 管理端

- 重复开放批次：阻止并指出当前开放批次。
- Excel 导入：逐行验证；不合法行不写入，下载错误行和原因。
- 关闭仍有未完成任务的批次：二次确认。
- 导出失败：允许重试，不改变数据库。
- 批量操作：先展示影响数量并二次确认。

所有用户提示使用通俗中文；服务端日志保留内部错误码和请求 ID，页面不展示堆栈或数据库细节。

## 14. 安全与隐私

- 生产环境仅允许 HTTPS。
- 管理密码只保存摘要和盐值，不进入前端包、源码仓库和日志。
- 管理 Cookie 为 `HttpOnly + Secure + SameSite=Lax`，两小时失效。
- 管理写请求同时校验 Origin 和会话绑定的 CSRF 令牌。
- 登录、身份匹配和提交接口按 IP 与时间窗口限流。
- 所有输入限制长度、枚举值并进行服务端校验；导入文本按纯文本处理。
- 任务 ID 使用高熵随机值，读取题目还需要短期任务令牌。
- 公开接口从返回模型上排除评分人列表、答卷、分数和汇总结果。
- 匿名 PNG/PDF 不含评分人姓名；含身份的 Excel 仅管理员可用。
- 数据长期保存，历史数据优先停用、归档或作废，避免物理删除。
- 永久清理仅限已归档批次，必须先备份、二次确认并留下不含评分明细的审计记录。
- 任何敏感数据导出后由管理员负责安全保存和传输。

## 15. 备份与恢复

- 每周由定时云函数导出业务集合，以 AES-256-GCM 加密后写入备份存储。
- 备份密钥只保存在 CloudBase 环境变量中，不与备份文件同处。
- 自动备份保留 90 天；过期备份按生命周期清理。
- 管理员每月导出一次完整 Excel 并离线保存。
- 批量清理历史数据前必须先生成一次备份并记录日志。
- 上线前在独立测试环境完成一次恢复演练，验证人员、任务、答卷和结果数量及抽样分数一致。

## 16. 测试与验收标准

### 16.1 单元测试

- 210 道题、42 个维度、7 个职位的数量、唯一编号和顺序校验。
- A—E 与“无法判断”的分值映射。
- 单维 0—5 道有效题的边界。
- 同层级多人平均、三个层级权重、任意层级缺失归一。
- 六维缺失时不生成雷达图和综合分。
- 姓名与部门规范化、时间截止判断、历史兼容判断。

### 16.2 服务集成测试

- 一个职位只能有一个开放批次。
- 任务查找只返回对应评分人的任务。
- 事务保证一条任务只有一份当前有效答卷。
- 同一幂等键重试只创建一次答卷。
- 作废后旧答卷不计分、任务可重填。
- 批次关闭冻结，重开使旧快照失效。
- 公开接口无法读取评分人身份、答卷和结果。

### 16.3 端到端测试

- Android 微信浏览器、iOS 微信浏览器/Safari、桌面 Chrome/Edge 的主要流程。
- 六页问卷、返回修改、草稿恢复、提交后清除。
- 管理员人员导入、批次创建、任务分配、进度查看、作废重填。
- 同职位历史图正确叠加，跨职位不叠加。
- PNG、PDF、Excel 中的人员、职位、批次、分数和样本数一致。
- 公开页面、PNG、PDF 和生产前端构建文件均不含管理密码或评分人姓名列表。

### 16.4 并发和恢复

- 模拟 20 名评分人同时提交，所有有效请求均保存且不重复。
- 模拟提交成功后响应丢失，重试得到原结果。
- 从自动备份恢复到测试环境，集合数量、关联关系和抽样分数一致。

验收时运行自动化测试、生产构建、移动端手工流程、并发测试和一次恢复演练；上述项目全部通过后方可正式开放问卷。

## 17. 实施拆分

为了降低一次上线的风险，实施按以下顺序完成，但属于同一第一版规格：

1. 共享题库、计分引擎、CloudBase 数据层和鉴权基础。
2. 公开职位问卷、任务匹配、草稿、提交和幂等。
3. 管理员人员、批次、任务和完成进度。
4. 汇总结果、能力图、历史对比和三种导出。
5. 安全限流、到期任务、备份恢复、并发与全流程验收。

每阶段均先完成对应自动化测试，再接入下一阶段；正式环境只在完整验收后启用。

## 18. 最终决策摘要

- 技术方案：EdgeOne Makers 前端 + 腾讯云 CloudBase 后端。
- 任务模式：管理员预分配“谁评价谁”和评分层级。
- 评分人识别：姓名 + 所在部门，接受基础核验的安全边界。
- 题目：每职位 6 维 × 每维 5 题；A—E 及无法判断。
- 计分：20—100 分，单维至少 3 题，同层先均分，再按 50%/30%/20% 加权并对缺失层级归一。
- 能力图：六维都有有效样本后才生成；缺失项显示待补充。
- 历史对比：只比较同一人员、同一职位、相同维度标识。
- 报告：PNG/PDF 匿名；Excel 含评分人明细且仅管理员导出。
- 重填：管理员作废旧答卷，保留审计记录后允许重填。
- 数据：云端长期保存，每周加密备份，自动备份保留 90 天。
